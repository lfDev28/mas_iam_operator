# mas-iam-operator

A Helm-based operator, scaffolded with operator-sdk and run by `helm-operator` v1.33.0. It watches `MasIamStack` resources (`iam.mas.ibm.com/v1alpha1`) and reconciles each one as a release of the [`mas-iam-stack`](helm-charts/mas-iam-stack/README.md) chart, which deploys Keycloak, PostgreSQL, and OpenLDAP.

`mas-est install` installs the operator through OLM. It applies `manifests/install-olm.yaml` (CRD, RBAC, a CatalogSource in `openshift-marketplace` pointing at the catalog image, an OperatorGroup, and a Subscription). Then `scripts/install-olm-sample.sh` applies `manifests/install-olm-sample.yaml`, which contains the demo secrets (password `maxadmin`), the OpenLDAP TLS generator Job, and the `MasIamStack` named `mas-est-iam`. For installation, see [docs/GUIDE.md](../../docs/GUIDE.md).

## Layout

| Path | Contents |
| --- | --- |
| `watches.yaml` | Maps `MasIamStack` to `helm-charts/mas-iam-stack` |
| `helm-charts/mas-iam-stack` | The chart. `charts/mas-iam-stack` at the repo root is a symlink to it; `make lint` at the repo root checks the link |
| `Dockerfile` | `helm-operator` base image plus `watches.yaml` and the chart |
| `config/` | Kustomize: CRD, RBAC, manager, samples, scorecard, CSV base (`config/manifests`) |
| `bundle/`, `bundle.Dockerfile` | Generated OLM bundle (`make bundle`) |
| `index*.Dockerfile` | Catalog image Dockerfiles generated by `opm` |
| `Makefile` | `VERSION` (operator version), build, deploy, bundle, and catalog targets |

`bin/` is gitignored. The `kustomize`, `helm-operator`, `operator-sdk`, and `opm` make targets download these tools into it when they are not already on `PATH`.

## Develop

Iterate on the chart with plain Helm first. Template rendering needs the three secret names that the chart refuses to default:

```bash
helm lint helm-charts/mas-iam-stack
helm template t helm-charts/mas-iam-stack \
  --set keycloak.bootstrapAdmin.secretName=a \
  --set openldap.admin.secretName=b \
  --set openldap.userPasswords.secretName=c
```

Run the operator against the current kubeconfig without building an image:

```bash
make install   # apply the CRD
make run       # helm-operator run, from this directory
```

Or deploy a built image with `make deploy IMG=<image>`. Remove it with `make undeploy` and `make uninstall`.

## Build

The cluster is amd64. On Apple Silicon, pass `--platform linux/amd64` to every build. The `docker-build` and `bundle-build` make targets do not pass a platform, and `catalog-build` has `opm` build the image itself, so on an arm64 host all three produce arm64 images that crash on the cluster with `exec format error`.

```bash
podman build --platform linux/amd64 -t <registry>/mas-iam-operator:<version> .
```

The repo's manifests expect the catalog image at `mas-iam-operator:catalog-<version>`. That differs from the Makefile's default `CATALOG_IMG` (`mas-iam-operator-catalog:v<version>`), so always set `CATALOG_IMG` explicitly.

## Release

Use the `/mas-est-release` skill, §9 ([.claude/skills/mas-est-release/SKILL.md](../../.claude/skills/mas-est-release/SKILL.md)). It has the platform-safe image, bundle, and catalog sequence, and lists every file that pins the operator version. Publish the operator before any CLI release that bundles manifests pointing at the new catalog tag.

## Dev scripts (repo root)

| Script | Purpose |
| --- | --- |
| `scripts/dev-generate-openldap-tls.sh -n <ns> -r <release>` | Recreate `<release>-keycloak-openldap-tls` locally |
| `scripts/test-openldap-bind.sh -n <ns> -r <release>` | Run `ldapwhoami` against OpenLDAP with the admin secret |
| `scripts/export-keycloak-realm.sh <ns> <release> <realm> [out]` | Export a realm JSON into `realm-config/` |
| `scripts/mirror-dev-images.sh --dest <repo>` | Mirror the Docker Hub PostgreSQL and OpenLDAP images, keeping all architectures |
| `scripts/reset-namespace.sh -n <ns> [--purge-tls] [--force]` | Delete the stack, its secrets and PVC, and the namespace-scoped OLM objects |
